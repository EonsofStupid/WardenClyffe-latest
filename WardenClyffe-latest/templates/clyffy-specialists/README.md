# Clyffy Specialists — Template Index

Specialists are Clyffy's team of minions. Each specialist owns one
namespace from `wardenclyffe/registry/context-mesh.yaml` and exposes a
small, well-scoped capability set through an MCP server.

The canonical contract lives in
[`docs/CLYFFY_SPECIALIST_NAMESPACE_DECISIONS.md`](../../docs/CLYFFY_SPECIALIST_NAMESPACE_DECISIONS.md).
Read that first.

## How to instantiate a specialist

1. Pick the namespace from the ten listed in the decisions doc
   (Decision 3).
2. Copy `_skeleton/` to `<namespace>/` (keep the namespace directory name
   matching the canonical id segment — e.g. `authentik/`, `proxmox/`).
3. Fill in `manifest.yaml`, `touchpoint.md`, and `seed.template.yaml`
   with the namespace's seeded defaults from the decisions doc.
4. For the MCP wire contract — the actual `tools.yaml`, `resources.yaml`,
   `policy.yaml`, `observability.yaml`, `evals.yaml` — derive from the
   deeper template at
   `wardenclyffe/.agents/templates/mcp-mesh-server/`. The product-level
   skeleton here is intentionally thin; do not duplicate that content.
5. Run the attunement pass (`wc-specialist attune <namespace>` — not yet
   implemented; tracked as M-next after the MCP renderer ships per
   `docs/MCP_CLIENT_NORMALIZATION_SPEC.md` M5) to populate the
   project-specific seed values from RRD projections.

## Two layers of knowledge

| Layer | Source of truth | Update cadence |
|---|---|---|
| Default capabilities | This template + the deeper MCP-mesh-server template | PR per change |
| Seed values (project-attuned) | Generated by attunement from project artifacts → RRD | On project artifact change |

The specialist queries the RRD at runtime for project context; it does
not re-read project files on every call. This is the passive-intelligence
principle from
[`docs/ai/HYBRID_INTELLIGENCE_LAYER_NORTHSTAR.md`](../../docs/ai/HYBRID_INTELLIGENCE_LAYER_NORTHSTAR.md)
applied to specialist onboarding.

## Notes

- The new IDs above are targets pending ratification of provisional
  ADR 0035 (per the decisions doc). The registry today still uses the
  old form; do not write code against the new IDs until the rename
  lands.
- The skeleton is the *product* shell. The MCP-wire shell is the deeper
  nested template. Both are real and both get filled in for each
  specialist; this README points at the seam.
