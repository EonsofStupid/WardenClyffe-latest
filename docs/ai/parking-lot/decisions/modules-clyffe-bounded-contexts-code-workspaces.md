- **[capability] Verified per-tool auth + keep-alive catalog (June 2026 research)** (locked 2026-06-11): Locked 2026-06-11 from sourced June-2026 research. Auth commands behind the Connect&Launch buttons: Claude Code — 'claude' (browser OAuth) or 'claude setup-token' -> CLAUDE_CODE_OAUTH_TOKEN; creds at ~/.claude/.credentials.json (0600), persist across SSH/reboots, ~1yr, auto-refresh on HTTP 401; DURABLE keep-alive via the 'apiKeyHelper' setting = a script that fetches a token from Infisical / /run/warden-secrets every ~5min (this is the no-leak persistence path and ties to the secrets-exclusion guard). Codex — 'codex login' (ChatGPT) or 'printenv OPENAI_API_KEY | codex login --with-api-key'; ~/.codex/auth.json; auto-refresh; '--device-auth' is beta. GitHub — 'gh auth login --with-token' or GH_TOKEN env; system credential store. Gemini — use GEMINI_API_KEY (NO reliable built-in headless OAuth; OAuth cache ~/.gemini/oauth_creds.json). HARD CAVEATS that reshape the UI: (1) Cursor is NOT authenticated on the devstation — AI auth is local-client; the remote only runs ~/.cursor-server execution host, so a 'Cursor auth on devstation' tile is a category error (only an SSH-host entry belongs there). (2) Antigravity = GUI Google-OAuth only, NO headless login, and its AGENT does NOT work over Remote-SSH (only the IDE shell does) — cannot be a turnkey remote tile yet. Conclusion: remote-auth tiles = Claude Code, Codex, gh, Gemini(API-key); Cursor + Antigravity = local-client connect, not on-devstation auth. Also: from 2026-06-15 Agent SDK / non-interactive 'claude -p' usage on subscription plans draws a separate monthly Agent SDK credit.
